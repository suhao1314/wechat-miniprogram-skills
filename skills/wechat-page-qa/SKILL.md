# 微信小程序真实页面验收

## 新对话与其他 AI 的入口

本目录是独立技能，不依赖原项目的代码或聊天记录。首次接手请读取 [跨 AI 接手说明](references/portable-handoff.md)，按当前机器发现 CLI、项目和图片查看工具。`agents/openai.yaml` 仅供支持该格式的宿主使用；其他 AI 可直接读取本文件与相对链接，不必解析该文件。

先确认本机文件读取、终端执行、桌面工具访问、图片查看四项能力；缺一项就说明缺口，不假装已操作。下面提到的 `view_image` 指宿主提供的本地图片查看工具，不要求其他 AI 具有同名 API。纯网页聊天且不能访问本机时只能指导用户执行或审图。

## 启用与边界

仅在用户明确同意本次接管开发者工具后使用；用户已明确要求本次页面验收时不重复询问。本技能设为手动启用。不要因为改了代码就自动接管正在使用的 IDE。

用户要求“全流程开发”时，本技能负责开发前探测与开发后的真实页面验收，不代替业务需求、权限审查或生产验收。开启之前确认项目、目标路由、状态、预期交互和截图目录。

不自动上传、发布、部署云函数、清缓存、关窗口、重装、改安全设置或提交生产业务。付款、退款、提现、删除、审核通过等按钮不能作为普通点击探针。遇到授权、令牌、账号权限门禁，停在真实边界并请求用户配合。

## 工具入口

优先使用当前安装的官方 `wechatide`，读取安装包内根 `SKILL.md` 与对应场景、`--help`。不要把 `cli.bat agent tool` 当作它的同义入口；本机曾因此得到 `agent.skills is empty in app.json`，不应为此给业务 app.json 添加 AI 配置。

命令及其适用条件见[操作参考](references/portable-handoff.md)。只需连接、确认路由和截图时，可在用户批准的非沙箱桌面环境运行：

```powershell
& ./scripts/probe-page.ps1 -ClientName '实际AI产品名' -ProjectPath 'D:/project' -Page 'pages/example/example' -Selector '.page-root' -OutputDirectory 'D:/workspace/99-temp/page-qa' -Approved
```

脚本只验证基础链路，不会点击业务按钮或注入数据，不证明整个页面或业务通过。脚本若返回失败，不能继续把失败截图当成目标页面。

脚本适用于本次验证的 Windows 官方安装结构，可传 `-CliPath`；其他系统按接手说明直接调用官方 CLI，不把 Windows 安装路径照搬。clientName 必须是实际 AI 产品名并与授权弹窗一致；同一会话保持不变，不能冒充已授权的其他 AI。

## 验收门槛

1. 登录与版本：官方状态检查成功、登录未过期、skill 版本匹配；不在输出中保留登录用户的 OpenID、头像或令牌。
2. 运行时：实际页栈包含目标路由。开窗/导航/刷新返回 success 只证明命令受理；空页栈、编译中截图都不算打开成功。
3. 编译：检查目标 WXML、WXSS，必要时检查页面注册和控制台。局部编译通过不代表整包运行通过。
4. 交互：选择明确无业务副作用的控件，读取变更前状态，真实点击，再读取状态并断言变化；需要时还原。不要只调用页面方法冒充点击通过。
5. 视觉：拿真实模拟器截图，用 view_image 打开，与已确认设计对照颜色、文字、留白、图片、按钮和安全区；另检查长文、空状态与失败态。用 HTML 镜像或生图不能代替真实小程序截图。
6. 收尾：恢复临时状态/函数，列出截图与剩余问题。真实账号、权限、通知、支付退款与真机兼容单列，不能靠模拟器宣布通过。

## 窗口复用、内部截图与异常分流

- 先读取同一绝对项目路径的运行时并复用当前会话；页面路径不同不等于窗口没开，读取超时也不等于窗口没开。禁止据此再次启动 IDE、重复开窗或启动另一份 Electron。
- 只有已确认目标项目窗口确实未打开，才允许一次 `open_project_window`。无法确认时询问用户，不猜测。脚本默认禁止开窗，`-OpenIfConfirmedAbsent` 仅用于已核实窗口不存在的情况。
- 页面证据只用 `simulator_screenshot --project ...` 从模拟器内部获取。禁止用桌面、活动窗口或屏幕区域截图替代；不能抓到用户正在使用的其他软件。不要为截图抢焦点、置顶、移动用户窗口。被其他窗口遮挡不应改用桌面截图；最小化、停止渲染或锁屏是否可用需实测，不能保证。
- 每张截图必须用 `view_image` 查看。路由正确、选择器存在、文件非空或尺寸正确，都不能代替查看图像。截图脚本仅返回 `visualReviewed=false`，不自动宣布页面正常。
- 白屏、编译中、错误页、错误页面、关键内容缺失均属于验收失败。保留截图；读取当前路由及 `get_simulator_console --command 'grep -i error'`。无匹配时可用 `grep -n .` 补上下文，无匹配不等于没有错误。必要时核对 WXML/WXSS 编译与网络失败。
- 明确的本地代码缺陷且任务已授权修复时，作最小修复，再编译、读路由、截图、看图；仅查验或定位原因的任务不自动改业务代码。原因不明、日志取不到、重复恢复失败、涉及权限/线上数据时停止，告诉用户目标路由、现象和日志取得情况，并请用户确认错误页。
- 控制台可能包含手机号、OpenID、取件码和令牌。只保留与问题有关的脱敏片段，不把原始全量日志写进技能、公共仓库或最终回复。

## 恢复与停止

- 首次 `CONNECT_ERROR`：按官方授权流程处理，固定 clientName，不翻找凭证、不换名字绕授权。
- 编译中或 `rawPath ... null`：先读取逻辑层页栈与编译证据。若已证明运行时可执行但页栈为空，允许一次受控刷新与一次明确路径的 reLaunch，然后重核路由。不要把本次恢复当作所有超时的通用修复。
- 同一恢复仍失败：保存最小错误与初始截图，按当前官方说明诊断；不持续刷新、反复开窗或无条件加长等待。
- Mock 只改内存展示，显式标“本地示例”，保存并恢复原状态；检查 onShow/onHide/onUnload/自动保存与状态核验钩子，避免伪订单触发云操作或污染草稿。
- CLI 可能进程退出码为 0 但 JSON `ok:false`，必须检查结构化结果。Windows `.cmd` 会丢失未正确转义的 JSON 引号；不要把传参错误误判成业务错误。

只有“连通、路由、编译、交互、视觉”分别有证据，才可报告本次页面验收通过。保留已发现的布局问题，不以“截图成功”掩盖设计偏差。
