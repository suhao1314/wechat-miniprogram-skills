# 原生报名样板

这是一个可直接导入微信开发者工具的纯本地演示。它不连接云开发、支付、真实账号或真实用户数据。两位虚构身份、草稿和报名记录都使用当前设备的本地存储。

## 导入与手工验证

1. 微信开发者工具选择“导入”，项目目录选本目录。项目没有绑定可公开使用的 AppID。若你当前版本的开发者工具不接受 `touristappid`，在你自己的本地开发副本中填写一个你有权使用的测试 AppID 或项目 AppID，再导入。不要把该 AppID、密钥或项目配置回传到公开样板。
2. 打开首页。输入备注，无需点保存，刷新或关闭再打开项目，林同学仍应看到自己的备注。切到乔同学，备注应为空。
3. 点“模拟一次失败”，再点“确认报名”。应显示失败、记录仍为 0 人，备注仍在。再点“确认报名”，应变为 1 人。
4. 再点一次“确认报名”。应显示已经报名成功，记录仍为 1 人。
5. 手动点右上角分享。接收者打开的是同一公开报名入口，不携带本机草稿或身份参数。

## 一条可重跑的回归命令

需要 Node.js 18 或更高版本。在此目录运行：

```powershell
node --test tests/signup-service.test.js tests/signup-page.test.js
```

这条命令覆盖同一份业务服务和页面入口里的草稿隔离、输入即保存、页面重建恢复、一次提交失败和重复报名幂等。`tests/` 和本说明已写入打包忽略，不会进入小程序包。它不等于微信开发者工具、真机、跨设备或云端并发测试。

## 稳定定位点

页面用 `data-testid` 标记 `user-lin`、`user-qiao`、`note`、`save-draft`、`simulate-failure`、`submit`、`status`、`booking-count`、`reset` 与 `ui-cases`。自动化工具支持 WXML/CSS 定位时可用它们。当前目录下的交互正反例页由主 Skill 维护。

本样板测试同一设备、同一活动及虚构身份的重复报名。不同手机同时抢同一个名额需要共享后端及事务等约束，应独立在测试云环境验证。

Windows 用户需要重复跑模拟器实测时，先把本目录复制到独立测试目录，在微信开发者工具中打开该副本并登录。保持页面可编译，确认可以清空本样板的虚构报名记录。安装包提供官方 wechatide CLI 并加入 PATH 时，可从主技能根目录执行：

```powershell
./scripts/verify-signup-devtools.ps1 -Project "D:/demo/signup-demo" -Output "D:/demo/new-evidence" -ClientName Codex -ResetDemo
```

每次指定一个新的证据目录。工具需要当前 AI 的桌面授权。本机只会验证草稿恢复、模拟失败和重复报名，执行时不需要云端账号或费用。
