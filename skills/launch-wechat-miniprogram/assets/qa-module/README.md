# 可复用问答模块样板

这是一个可带进不同微信小程序的业务模块参考。它负责问题、回答、待审和权限边界。它不替任何项目决定谁能发布、什么时候公开、谁审核或应选哪个类目。

## 已验证的两个宿主

运行 `npm test`，会启动两个互不共享数据的宿主。

| 宿主 | 发布策略 | 回答者 | 已验证结果 |
| --- | --- | --- | --- |
| 校园问答 | 提问先待审 | 管理员 | 提问者能看待审问题，另一位学生不能读取或编辑，管理员发布后才对其他学生可见。 |
| 学习辅导 | 提问直接公开 | 导师或管理员 | 学员不能冒充导师回答，导师回答后其他学员可读。 |

运行结果只代表 Node 的业务规则和内存存储。接入云数据库后，还要用测试账号验证云函数身份、集合规则、并发和真实页面。

## 接入一个项目

1. 复制 `src/qa-service.cjs`，不要把 `authorId`、角色或审核状态交给页面传入。
2. 给项目实现 `repository` 的五个方法，并让身份服务在服务端提供当前用户。每个项目独立选择集合、索引、审核策略和保留期限。示例默认 ID 用 Node 内置的 `crypto.randomUUID()` 生成，真实数据库仍应对唯一性和并发写入负责。
3. 从 `miniapp/cloudfunction/index.js` 开始接云函数。部署时把 `src/qa-service.cjs` 一并放入该云函数目录，并把其中的相对 `require` 改为 `./qa-service.cjs`。它用 `cloud.getWXContext()` 获得身份。`repository.js` 故意没有默认实现，防止把内存示例误部署到生产。
4. 在页面调用云函数时只传 `action` 和 `input`。路由器会只转发允许字段。页面不传 OpenID、角色、审核状态、回答作者或其他用户的 questionId 所有权。
5. 复制其中一个测试宿主，按当前项目的角色和审核政策改用例，测试同名用户、其他用户读写、管理员审查、待审内容、下架、重复提交和分享入口。

## 最小调用示例

```js
// 前端只提交用户填写的内容。身份来自云函数的 getWXContext。
wx.cloud.callFunction({
  name: "qa",
  data: { action: "createQuestion", input: { title: "怎样报名？", body: "请说明报名截止时间。" } }
});
```

## 交付前需要项目负责人确认

- 谁可提问、回答、审核、查看待审与已下架内容
- 是否允许编辑，编辑后是否重新待审
- 举报、申诉、处理负责人和处理时限
- 内容安全能力、隐私说明、服务类目与当前主体条件
- 数据保留与注销处理，公开分享是否提供可撤销、可重新鉴权的入口

本样板不含 UI、数据库规则或内容审核服务，避免把一个项目的品牌、用户数据、资质假设和权限直接复制到另一个项目。
