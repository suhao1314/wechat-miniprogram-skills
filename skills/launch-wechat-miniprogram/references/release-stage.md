# 发布阶段

发布包含上传、体验版、审核、正式发布和上线后的基本维护。始终解释：上传代码、开发版本、体验版、提交审核和正式发布是不同状态。

已上线项目更新时先读取 [version-update.md](version-update.md)，确认 `docs/miniapp/version-change.md` 已写明当前线上版本、目标版本、云资源/身份/隐私影响、回退和回归范围。线上版本与开发中版本必须分别记录。

## 发布前基础检查

确认名称、头像、简介、服务类目、行业资质、隐私保护指引、用户协议、备案状态、后台连接、域名、版本号、页面截图和测试报告。使用腾讯云后台时确认 EnvId 硬门禁、云端资源预检表和云端写入校验通过；使用自有后台时重新检查 HTTPS、SSL、备案和服务器域名；使用网页容器时检查业务域名。

同时完成以下门禁：

- 运行 `python <skill-root>/scripts/validate_miniprogram_artifacts.py <project-root>`，修复所有错误；脚本通过只算 L1 静态证据。
- 记录开发者工具版本、基础库版本和实际打包范围；确认 `packOptions` 没有上传辅助资料或漏掉运行资源。
- 新流程重置、返回保留、关闭重开和分享冷启动符合已确认的状态生命周期。
- 分享给朋友与分享到朋友圈分别真机测试；受基础库或平台限制的能力明确标成“不支持/未测试”，不能写成通过。
- 云端写入的必填、长度、范围、归属、重复请求和越权测试通过。
- 通用代码审查没有未解决的阻塞级问题；建议和可选项已有决定。

## 安全验收单

把权限审查前移。设计含账号或共享数据的功能时，记录谁能对哪类数据做什么、由哪个服务端入口作决定。开发时对照本次改动检查该入口、数据库访问规则及相关导出或分享路径。纯本地工具只核对实际存储、依赖及网络使用。更新旧版本时优先复核发生变化的权限和共用入口。

报告中每个结论对应一处证据：已覆盖范围、预期规则、代码或配置位置、在什么环境看到了什么、仍缺什么。将“发现疑点”“证据确认”“修复已复核”分开。例如界面隐藏了导出按钮，只能证明该角色看不到按钮；审核者继续查导出服务对角色和数据范围的校验，补齐受限测试账号的正常权限回归。问题修复后用原角色重跑并记录结果。按影响给负责人排优先级，缺证据时保留待核状态。[Cloudflare 审查项目的覆盖与报告方法](https://github.com/cloudflare/security-audit-skill)

不要把“安全扫描没有报错”写成“程序安全”。按本项目实际提供的能力选用下表，并在 `test-report.md` 中写明版本、环境、操作者角色、测试动作、结果、证据位置和未验证原因。

| 项目类型 | 至少验什么 | 能证明什么 |
| --- | --- | --- |
| 纯本地工具 | 本地数据是否含敏感信息、卸载/换机后的预期、外部请求和第三方依赖 | 用户知道数据留在哪里，程序没有偷偷上传 |
| 有账号、报名、订单或后台 | 普通用户、另一名用户、管理员各走一次读写路径；篡改对象编号、角色或状态后再试 | 服务端按当前身份和数据归属授权，前端参数不能越权 |
| 用户内容或社区 | 发布、编辑、待审、举报、下架、复核和分享入口 | 待审或下架内容不会从列表、搜索、详情或分享提前公开 |
| 支付、权益或库存 | 重复点击、网络重试、并发抢名额、回调重复、金额和订单归属 | 一笔业务只生效一次，客户端不能改金额或冒领 |

已有项目保留历史报告，把新版测试和发布模板中的相关表格追加在本次版本名下。

安全验收优先使用测试账号、测试环境和脱敏测试数据。对生产数据的读取、权限修改、恢复、支付或通知，必须由负责人对具体目标和影响单项授权；没有授权时记录“未执行”，不能用猜测补成通过。发现跨用户读取、权限绕过、密钥泄露、错误扣款或公开暴露敏感资料时，按阻塞级处理，交给有权限的负责人决定暂停受影响入口，并记录修复与复测范围。

## 发布证据等级

沿用 [development-stage.md](development-stage.md) 的 L1-L7 证据等级。发布清单中的每个“已验证”都要能指向测试报告中的设备/环境、版本、日期、结果和证据位置；L1 静态检查、L2 编译或 L3 模拟器不能写成“真机通过”，L4 安卓不能替代 L5 iPhone，L6 体验版不能替代 L7 正式环境。

未执行的等级必须写“未验证”和原因。正式发布前至少明确当前最高等级和仍未覆盖的平台；发布后只有正式入口完成对应验证，才能记录 L7，不能仅凭平台显示“发布成功”推断所有功能正常。

## 危险操作发布门禁

发布回归默认不在真实环境自动执行真实支付/退款、创建真实订单、注销账号、删除或清空数据、解绑/解散/踢出成员、发送真实消息/订阅/外部通知等不可逆或产生费用的动作。优先使用测试账号、测试环境、沙箱、只读检查或可撤销的小额流程。

需要执行时，必须由用户针对具体账号、环境、金额或数据明确授权，并在执行前说明影响和恢复方式；授权不得扩展到批量或循环测试。未授权或不适合执行的项目在 `test-report.md` 和 `release-checklist.md` 记录“安全跳过”，既不算失败，也不能算通过。

## 审核专项门禁

体验版通过不等于审核材料已准备好。提交审核前逐项完成以下检查，并把结果写入 `release-checklist.md` 和 `test-report.md`。

### 审核员可达性和测试账号

为每个已申报类目和核心功能记录审核路径：

| 功能 | 首页入口 | 点击次数 | 是否要登录/付费 | 审核准备 |
| --- | --- | --- | --- | --- |
| 示例：创建订单 | 首页“立即下单” | 2 | 需要登录 | 测试账号已准备 |

- 已申报类目对应页面应从首页直达或两次点击内到达；入口不得只藏在搜索、分享链接、灰度开关或未公开菜单中。
- 登录后、会员、付费、地区限制或特定角色才能看到的功能，准备可体验完整流程的测试账号、入口和编号步骤。审核账号应在提交前真机登录一次，确认没有失效、强制短信验证或空数据阻塞。
- 只在发布清单记录“测试账号已准备、入口、角色、验证日期、审核说明位置”。账号、密码、验证码和身份证信息不要写入仓库；按平台当前提供的安全入口填写审核资料。
- 有账号体系时提供正常、易发现的退出账号入口；需要注销能力的业务同时验证注销、数据删除和重新登录路径。

### 隐私接口与平台指引一致

按当前提审代码生成隐私能力清单，不要沿用旧版本记录。至少搜索并真机核对头像昵称、手机号、定位、相册、文件、摄像头、麦克风、剪贴板、通讯录及其他受保护能力；第三方 SDK 间接调用的能力也要列入。

把“实际调用能力、触发页面、用途、是否必需、拒绝后的表现、平台隐私保护指引条目”逐项对应。新增、删除或改变用途后同步更新微信公众平台。指引为空、用途不真实、代码调用与指引不一致，或拒绝授权后主链路无合理降级时，不得提审。

### 诱导分享、关注和外部导流

检查按钮、弹窗、浮层、任务、积分、福利和文案：

- 不要求用户分享给朋友或朋友圈后才能继续使用、领取必要权益或查看结果。
- 不要求关注公众号、添加个人账号/群、下载其他应用或跳转外部服务后才能使用小程序核心功能。
- 正常分享功能可以保留，但入口、结果和奖励不得构成强制或误导；分享给朋友和朋友圈分别按真实平台能力描述。
- 客服、公众号和外部链接存在时，核对当前平台规则、业务必要性和用户可跳过路径。

### 完整产品和账号闭环

审核体验必须像可用产品，而不是测试壳。检查首页、所有核心入口、返回、底部导航、按钮响应、加载、空数据、错误、拒绝授权和弱网。删除“测试中”“占位页”“敬请期待”等会阻塞已申报功能的页面；不能只有一个页面或一个无结果按钮。

有账号体系时同时检查登录、退出账号、资料修改、注销或删除数据等适用路径。任何崩溃、白屏、死链、按钮无响应、无法返回或审核员无法完成主流程的问题都按阻塞级处理。

### 用户内容安全和第三方服务

允许用户提交文本、昵称、评论、图片、音视频或公开分享内容时，明确发布前、展示前或异步审核的内容安全策略，以及举报、删除和处置路径。不能只在前端过滤关键词。

列出第三方 SDK、统计、地图、客服、支付、AI、存储和外部后台，核对实际收集数据、用途、权限、隐私披露、失败降级和服务责任。移除未使用的 SDK 与权限；无法解释的数据收集或未披露的第三方调用按阻塞级处理。

### 交易、虚拟服务和主体限制

只有项目涉及商品、会员、课程、充值、数字内容、虚拟服务、金融、医疗、教育、食品等业务时才进入本分支。提交审核前重新查看微信公众平台当前账号可选类目、资质、支付和交易规则，以及实际目标平台限制。

不要把“个人小程序不能做电商、金融、医疗、教育”或“iOS 虚拟商品固定使用某种支付方式”写成永久结论。把这些历史说法作为风险触发词：打开当前官方页面，记录细分类目、主体、资质、支付方式、争议处理要求、核验日期和证据；无法确认时标记阻塞并让用户决定调整主体、缩小功能或补充资质。

官方参考：[小程序平台常见拒绝情形](https://developers.weixin.qq.com/miniprogram/product/reject.html)、[用户隐私保护指引](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)、[虚拟服务交易纠纷处理细则](https://developers.weixin.qq.com/miniprogram/product/jiaoyilei/xunifuwuxize9341.html)。

### 旧登录与支付代码扫描

按 [development-stage.md](development-stage.md) 搜索旧 `wx.getUserInfo`、`wx.getUserProfile`、前端保存或上传 openid、前端持有商户密钥、固定 MD5 支付签名及信任客户端金额的写法。旧代码可以作为迁移输入，不能作为当前审核通过依据；前端身份越权或支付密钥问题未修复时不得进入体验版和提审。

## 上传与体验版

给新手逐步指导：

```text
[ ] 1. 在微信公众平台添加需要参与测试的体验成员
[ ] 2. 在微信开发者工具中点击“上传”
[ ] 3. 填写版本号和本次修改说明
[ ] 4. 登录微信公众平台并进入版本管理
[ ] 5. 找到上传的开发版本，按当前页面设置为体验版
[ ] 6. 获取体验二维码，让体验成员扫码
[ ] 7. 测试核心流程、状态恢复、分享、授权、后台、域名、打包范围和真机表现，并记录最高证据等级
[ ] 8. 按审核专项门禁模拟一次审核员体验
[ ] 9. 记录阻塞/建议/可选问题，修复阻塞项后重新上传和体验
```

体验版只有被添加的人员可使用，不是公开上线。平台菜单变化时让用户发送打码截图，不猜具体按钮位置。

官方参考：[协同工作和发布](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/release.html)、[小程序 CI](https://developers.weixin.qq.com/miniprogram/dev/devtools/ci.html)。

## 提交审核和发布

体验版和审核专项门禁都通过后才提交审核。提交前准备：版本说明、服务类目、核心功能路径、测试账号状态、测试步骤、特殊角色/地区/付费说明、隐私接口对照结果和必要资质。敏感账号信息只填写到平台当前提供的安全位置，不进入项目文件或聊天记录。

审核被拒时先获取完整原文或打码截图，不在没有原文时盲改。按以下顺序处理：

1. 原样记录拒绝文字、页面、版本和日期。
2. 区分名称/简介、类目/资质、审核可达性、隐私授权、内容安全、诱导行为、交易支付或代码可用性。
3. 找到对应官方规则和实际复现路径，提出最小修改与回归范围。
4. 修复后重新走受影响的体验版和审核门禁，更新测试报告与发布清单。

审核通过后，仍提醒用户在微信公众平台执行正式发布。只有平台显示线上版本且用户能从正式入口访问时，才把 `progress.md` 标记为已发布。

## 上线后

记录线上版本、发布时间、已知问题和回退信息。使用腾讯云后台时检查错误日志、资源用量、费用提醒和数据备份；收集用户反馈，形成下一版本任务。每次更新重新走受影响的设计和环境门禁、开发测试、体验版、审核和发布，不直接覆盖线上结论。完成后运行 `python scripts/validate_project_state.py <project-root>`，状态存在错误时不能宣称版本闭环完成。

正式入口验证后，按[运营与收入验证](operations-and-revenue.md)给负责人一张首周行动单。用户只想稳定维护时，保留日志、费用与故障交接即可。

### 故障响应和恢复演练

上线前指定负责人和可用联系路径，记录在发布清单。负责人至少能回答“谁看告警、谁可以暂时关闭入口、谁负责向用户说明”。小团队可由同一人承担，但不能只写“管理员”。

| 情况 | 先做什么 | 何时恢复或继续 |
| --- | --- | --- |
| 大量报错、登录失败或数据异常 | 记录版本、时间、影响入口和脱敏日志；暂停相关发布或入口，保留证据 | 修复在测试环境复现并通过受影响的回归后 |
| 权限或隐私疑似泄露 | 立即限制可疑接口、分享入口或管理员权限，记录受影响范围；不要在群聊或公开 Issue 贴用户数据 | 负责人确认修复、权限复核和必要通知方案后 |
| 费用或请求量异常 | 核对当前环境、调用来源和版本，按既定方案限流、关闭高耗入口或降级 | 用量恢复可解释，并确认不会影响核心数据 |
| 误删或数据损坏 | 停止会继续覆盖数据的写入，记录范围和最后正常时间；先在隔离环境验证备份 | 负责人授权具体数据、时间点和目标环境后恢复，并复核结果 |

至少演练一次与项目相称的恢复动作。纯本地工具可以演练“清空后重新导入/恢复说明”；有后台的数据项目应在测试环境从备份或导出副本恢复一小段脱敏数据，再核对数量、归属和核心入口。生产恢复、删除、覆盖或通知用户均不由 Skill 自动执行，必须单项授权。演练失败、没有备份或没有负责人时，记录为上线风险，不能勾选为已具备恢复能力。
