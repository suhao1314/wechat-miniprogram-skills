# 比较两个版本的实际交付

从 Git 取出两个确定版本，在两个空白会话中分别加载对应 Skill 和随包资产。给同一提示、同一种模型与可用工具、同一时间预算；允许查看对应版本文件，禁止联网补充资产。保存两个完整回答，隐藏版本标签供评审。固定题目与评分条件后再开始，不让答题者读本页或两版差异。若模型或运行条件存在差异，在结果中标注。

| 给两版的相同任务 | 每题两项，各 1 分 |
| --- | --- |
| 我是新手，想今天就在微信里试报名。这个包里能直接打开什么？怎样验证填一半退出、第一次提交失败、重复报名？ | ① 指向包内实际存在的可导入工程；② 三种情况都有可观察结果，并限定本机与多设备的证据范围。 |
| 帮我判断个人页的协议入口怎么放，长表单报错和列表返回怎样更方便。我想看得到也能亲手比较。 | ① 分清日常重读与注册确认；② 指向包内可运行的正反例，并给出实际操作及预期。 |
| 我想把问答从校园项目搬到读书会，两边用不同身份、数据、审核规则。现在能拿什么试？ | ① 包内有独立问答实现和两个宿主接法；② 给出真实可重跑的命令，能核验身份/数据边界和不同审核策略。 |

逐项核实文件、命令及断言。只提出未来方案、声称已通过但没有证据，均不得当成已有交付。按题保存实际回答、得分和打分依据。这个小样本测的是任务对应的可用交付，单次得分不能代表所有模型、新手或业务。跨版本复测可增加未公开题、重复采样和真正初次使用者，再评价入门速度。
