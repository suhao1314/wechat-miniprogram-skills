# 环境准备阶段

本阶段同时处理微信账号、开发工具、是否使用腾讯云后台、后台连接和备案。不要把这些外部操作说成智能体已经完成。

## 小程序账号与资料

入口：[微信公众平台](https://mp.weixin.qq.com/)。给新手编号：

```text
[ ] 1. 注册小程序账号
[ ] 2. 选择个人或企业主体
[ ] 3. 完成主体认证
[ ] 4. 设置名称、头像、简介和服务类目
[ ] 5. 获取 AppID
```

建议：名称直接表达用途，先查重，避免侵权、敏感词、夸大词和与实际功能不一致；头像用清晰的正方形图，缩小后仍能识别，不放二维码、电话、网址或未授权 Logo；简介用一句话说明给谁解决什么问题，只写已经实现的功能。

服务类目按用户实际使用场景选择而不是按技术选择。工具、预约、商品、内容、教育、医疗等只作为候选方向；最终以账号后台当前可选类目和所需资质为准。

## 主体、类目与资质核验

把“个人小程序不能做电商、金融、医疗、教育”等说法当成需要核验的风险提醒，不能当成永久规则直接回复用户。平台类目、主体开放范围、资质和支付能力会变化，而且“电商”“教育”等大类内部也可能存在不同细分类目。

遇到个人主体或受限业务时按以下顺序处理：

1. 用一句话写清实际提供的服务、是否交易、是否让用户发布内容，以及是否涉及健康、资金、课程、食品或其他专项服务。
2. 登录该小程序对应的微信公众平台，查看当前账号可选择的服务类目、每个细分类目的主体要求和资质材料；不要只依赖搜索结果、社区文章或历史截图。
3. 对商品交易、金融、医疗、教育、食品、内容付费等分别记录“可选类目、主体要求、资质要求、支付限制、核验日期和官方页面”。
4. 平台后台没有对应类目、要求的资质无法提供或规则仍不明确时，状态写“未验证/存在阻塞”，不要承诺可以开发并通过审核。
5. 业务性质变化时重新核验；不能用首版工具类的审核结论覆盖后来新增的交易、课程、问诊或资金功能。

面向用户时说明“当前账号后台显示什么”和“还缺什么材料”，不要给出“个人主体一律可以/一律不可以”的保证。

获取 AppID 时，引导用户登录微信公众平台，进入当前小程序，查找“开发管理/开发设置”中的开发者 ID。平台菜单可能更新，找不到时让用户发送打码截图。AppID 可以记录在项目规划文件中；不要复制或保存旁边的 AppSecret，也不要保存身份证照片、密码、验证码或支付密钥。

## 开发者工具：新建或导入

下载：[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。在用户可见回复中按步骤指导：

开始桌面操作前先让用户选择“我操作，你指导”或“你操作，我接手扫码和确认”。用户选择自己操作后不得继续控制界面。

1. 安装并打开工具，用管理员或开发者微信扫码。
2. 没有代码时点击“新建项目”，填写项目名称，选择项目目录，填写真实 AppID，并按已确认的后台方案选择是否启用云能力。
3. 已有代码时点击“导入项目”，选择包含 `project.config.json` 的项目根目录，检查 AppID 和小程序代码目录。
4. 明确告诉用户三个位置：项目根目录是包含 `project.config.json` 的目录；小程序目录由 `miniprogramRoot` 指定；云函数根目录由 `cloudfunctionRoot` 指定，具体函数位于其下的同名文件夹，例如 `cloudfunctions/matchApi/`。
5. 读取并记录 `libVersion`；使用特定微信 API 或组件前重新查它的最低基础库版本和兼容方式，不用“latest”代替兼容性判断。
6. 检查 `packOptions.ignore`、`packOptions.include` 和 `setting.ignoreUploadUnusedFiles`。路径以实际 `miniprogramRoot` 为基准；先列出预览/上传应包含和不应包含的内容，不照抄固定忽略清单。
7. 区分团队共享的 `project.config.json` 和个人开发工具设置；最终上传行为以实际项目配置和开发者工具结果验证。
8. 点击“编译”，先确认模拟器显示首页，再继续做页面开发。
9. 如果界面与描述不同，让用户截图；不要猜菜单名称。

官方参考：[项目配置](https://developers.weixin.qq.com/miniprogram/dev/devtools/projectconfig.html)、[npm 构建](https://developers.weixin.qq.com/miniprogram/dev/devtools/npm.html)。

## 是否使用腾讯云后台：用生活化问题判断

先问：

```text
用户换一台手机后，还要看到原来的数据吗？
不同用户要看到同一批内容吗？
要上传图片或文件吗？要在电脑上管理内容或订单吗？
要记录用户身份、历史记录、支付、AI 或定时任务吗？
```

全部不需要时，建议静态页面或手机本地保存；只需要当前手机记住时，不要为了“看起来完整”创建后台。任意一项需要时，再说明腾讯云后台的账号、实名认证、环境、数据库、存储、权限、日志、备份和费用。

用户确认使用腾讯云后，给出逐步清单：

```text
[ ] 1. 注册或登录腾讯云账号
[ ] 2. 完成实名认证
[ ] 3. 打开腾讯云后台控制台并创建环境
[ ] 4. 查看最新价格，选择免费或付费方案
[ ] 5. 按当前官方流程关联小程序 AppID
[ ] 6. 记录完整的环境编号（EnvId）
[ ] 7. 按设计创建数据库、文件存储和后台程序
[ ] 8. 设置访问权限、费用提醒、日志和备份计划
```

用户可以回复“1-4 完成，5 关联失败，6 不知道在哪里”，智能体只处理第 5、6 项。腾讯云账号就是所需账号，不要让用户再寻找一个不存在的独立 CloudBase 注册入口。

## EnvId 硬门禁

环境名称和环境编号不是一回事。环境名称是用户便于识别的标签，例如 `prod`；EnvId 是平台实际调用使用的完整编号，例如 `prod-xxxxxxxxxxxxxxxx`。不得把 `prod`、`test` 等环境名称直接写进 `wx.cloud.init({ env })`，也不得仅凭用户手工输入就把 EnvId 标记为已验证。

进入依赖云端的开发前，必须让以下三项一致：

| 检查项 | 证据 | 通过标准 |
| --- | --- | --- |
| 平台实际环境 | 控制台环境列表或可信环境查询工具 | 同时看到环境名称和完整 EnvId |
| 客户端初始化 | `app.js` / `app.ts` 中的 `wx.cloud.init` | `env` 等于上一步完整 EnvId |
| 只读云端诊断 | 已部署的只读函数或无写入查询 | 调用成功，且不返回 `INVALID_ENV` |

把环境名称、完整 EnvId、验证方式和日期分别写入 `project-plan.md`、`progress.md` 和 `test-report.md`。三项未全部通过时，状态只能写“EnvId 待验证”或“连接失败”，不得写“腾讯云环境完成”。遇到 `INVALID_ENV` 时先重新执行本门禁，不要先反复部署云函数或修改数据库权限。

## 后台连接与域名分支

- 只用腾讯云原生小程序接口：填写腾讯云环境编号，使用 `wx.cloud` 连接；通常不要求额外购买一个 API 域名。
- 使用自有后台：准备 HTTPS 域名、SSL、域名备案，并在微信公众平台的“开发管理/开发设置”中配置数据请求、文件上传、文件下载和长连接服务器域名。菜单变化时以用户当前页面为准。
- 使用网页容器：另外配置业务域名。
- 开发工具里跳过域名校验只用于本地调试，不能作为上线配置。

官方参考：[网络和服务器域名](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。

## CloudBase 部署回复模板

用户使用腾讯云原生小程序接口并询问部署或域名时，在具体步骤前明确说：

```text
1. 通过 wx.cloud.callFunction 调用 CloudBase 云函数，不需要填写或购买自有 API 域名；只有使用自有 HTTPS 后台或 web-view 网页时才进入域名配置分支。
2. 云函数运行时代码不会自动创建缺失的数据库集合；必须先在目标环境创建集合并设置权限，再部署和调用依赖它的云函数。
```

随后给出当前环境名称、完整 EnvId、云函数根目录、函数名、集合名和完成后的只读验证方式，不能只说“上传部署即可”。

## 备案

入口：[小程序备案操作指引（登录微信公众平台后查看）](https://mp.weixin.qq.com/)。把主体资料、负责人、短信核验、业务说明、类目和行业资质整理成清单。备案可与开发并行；实名和短信操作由用户完成，正式发布前重新检查平台要求的状态。
