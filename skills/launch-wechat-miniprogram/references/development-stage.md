# 开发阶段

开发包含规格、代码、后台资源、联调、模拟器和真机测试。不要把“代码生成完”当成“开发完成”。

## 进入条件

- 设计已确认，高保真原型存在。
- AppID 和开发者工具可用，项目能编译。
- 已明确不用后台、使用腾讯云后台或使用已有后台。
- 腾讯云后台的费用和额外步骤已由用户明确确认。

## 已有项目最小源码盘点

继续已有项目时，修改任何源码前先完成只读盘点；新项目仍先走需求、范围和设计门禁，不能用空目录扫描代替需求访谈。至少读取：

- `project.config.json`、`app.json`、页面和分包声明、`tabBar`。
- `miniprogramRoot`、`cloudfunctionRoot`、云函数目录和插件声明，包括 `plugin://` 引用。
- 已有组件库、公共组件、主题/公共样式、请求封装、存储方式和后台连接方式。

把结果写入 `docs/miniapp/project-plan.md`，使用以下五组，不因文件缺失而自行补全：

| 盘点组 | 必须记录 |
| --- | --- |
| 用户可见功能 | 页面、分包、导航、主流程和当前线上入口 |
| 基础设施 | 登录、存储、请求封装、后台、云函数、插件和组件库 |
| 管理能力 | 管理端入口、角色、内容/数据管理和运维方式 |
| 高风险能力 | 支付、退款、删除、清空、注销、消息通知和真实订单 |
| 未确认项 | 无法读取、配置与运行结果冲突、需要用户或真机确认的内容 |

盘点只陈述源码和配置能证明的事实。发现已有正式版本时转入 `version-update.md`；涉及 UI 时再按 `miniprogram-ui-adapter.md` 继承现有样式基线，不把新项目三套方案机械套到局部更新。

## 规格与任务

中大型项目读取 `spec-workflow`，依次确认 `requirements.md`、`design.md`、`tasks.md`。任务按用户可完成的闭环拆分，例如“浏览 -> 详情 -> 提交 -> 查看结果”，不要按文件名机械拆分。

## 小程序实现路由

1. 先读取 `miniprogram-development`，检查 `project.config.json`、AppID、小程序根目录、页面配置、本地资源和开发者工具路径。
2. UI 以批准的 HTML 原型和设计规格为基准，把成熟组件方案转换为原生 WXML/WXSS/JS/JSON。不要直接嵌入网页作为最终页面。
3. 默认优先使用原生 `tabBar`。存在图标时，`iconPath` 和 `selectedIconPath` 必须指向项目内真实存在的本地 PNG，不使用网络图片、SVG、iconfont 或 emoji。只有原生能力无法满足已确认设计时才使用自定义 `tabBar`，并增加安全区、选中态、页面同步和真机回归测试。

## 基础库与打包边界

第一次编译和每次准备上传前都检查：

1. 记录开发者工具版本和 `project.config.json` 的 `libVersion`。项目调用 API 或组件时，按微信官方文档核对最低基础库版本、平台差异和降级行为；使用 `latest` 不能替代兼容测试。
2. 以实际 `miniprogramRoot` 为根确认预览/上传内容。检查 `packOptions.ignore`、`packOptions.include` 和 `setting.ignoreUploadUnusedFiles`，不要把别的项目的忽略规则直接复制过来。
3. 如果开发文档、数据清洗脚本、测试夹具、源码映射或依赖目录位于小程序源码范围内，明确排除不应上传的内容；同时确认本地图片、组件和分包没有被误排除。
4. 使用开发者工具的实际预览或上传结果验证打包范围。`project.private.config.json` 适合个人设置，但不能当作团队和最终构建行为的唯一事实来源。

把基础库版本、`miniprogramRoot`、打包规则和验证结果写入 `docs/miniapp/test-report.md`。

## 小程序产物确定性校验

首次接手已有项目、页面/组件/分包/`tabBar`/云函数发生变化后，以及每次准备上传前运行：

```powershell
python <skill-root>/scripts/validate_miniprogram_artifacts.py <project-root>
```

脚本只读检查 `project.config.json` 和 `app.json` 是否可解析、`miniprogramRoot`、页面与分包四件套、本地组件、原生 `tabBar` 本地 PNG、`cloudfunctionRoot`、代码引用的云函数，以及明显会漏掉运行资源的 `packOptions`。退出码 `0` 表示这些静态产物检查没有错误，退出码 `1` 表示必须按输出的“返回阶段”修复。

该脚本不能代替开发者工具编译、模拟器、真机、体验版或正式环境验证。`packOptions.include/ignore` 的复杂运行时资源仍要用实际预览/上传结果确认；不得因为脚本通过就宣称小程序可以上线。

## 状态生命周期与分享边界

写页面逻辑前明确以下状态生命周期，并把选择写入 `project-plan.md` 或 `decisions.md`：

| 场景 | 必须决定 |
| --- | --- |
| 开始一轮新流程 | 清空哪些旧数据，保留哪些用户偏好 |
| 返回上一页或重新选择 | 表单、筛选和临时结果保留还是重置 |
| 切到后台或关闭后重新打开 | 从内存、本地存储、云端恢复，还是重新开始 |
| 多页面读写同一数据 | 唯一事实来源、更新入口和清理时机 |
| 接收者从分享链接冷启动 | 是否能仅凭路径参数或后台记录重建页面 |

不要为了统一形式硬编码一套全局状态 API。只要求状态入口和清理规则明确，避免多个页面无约束地改写同一份全局数据。

分享目标依赖发送者本机缓存时，接收者无法复现该页面。此时应分享一个不依赖本机状态的稳定入口，或者在用户确认需要后设计可撤销、可鉴权的后台 `shareId` / 可复现参数。分享参数不得携带手机号、openid、密钥或其他敏感数据。

## 腾讯云后台路由

用户确认腾讯云后台后：

1. 读取 `cloudbase` 并确认完整环境编号。
2. 先创建或确认数据库集合、文件存储、云函数和安全规则，再写依赖这些资源的页面。
3. 身份读取 `auth-wechat-miniprogram`；数据库读取 `cloudbase-document-database-in-wechat-miniprogram`；后台程序读取 `cloud-functions`；支付读取 `cloudbase-wechat-integration`；AI 读取 `ai-model-wechat`。
4. 使用 `wx.cloud`；不要把 Web SDK 登录流程放进小程序。
5. 云函数通过 `getWXContext()` 获取可信身份，不接受客户端传来的 openid 作为登录证明。

## 云端写入校验

所有新增、修改、删除和提交类操作都要在云函数或可信后台重复校验，不能只依赖前端控件：

- 检查必填字段、类型、长度、枚举值、数值范围和对象归属。
- 对文本做必要的规范化和内容安全处理；明确重复提交、幂等和并发策略。
- `createTime`、状态、所属用户和审计字段由可信服务端生成；openid 只从 `getWXContext()` 等可信上下文取得。
- 返回对用户可理解的错误，但日志和错误响应不泄露密钥、完整个人资料或内部堆栈。
- 为无权限、非法输入、超长输入、重复请求和后台异常建立测试用例。

## 云端资源预检表

写依赖云端的页面前建立预检表；更新已上线项目时按目标版本重新检查受影响资源。每一项都记录“目标值、验证方式、结果”，不能只写“已配置”。

| 资源 | 必查内容 | 通过标准 |
| --- | --- | --- |
| 环境 | 环境名称、完整 EnvId、AppID 关联 | 平台环境、客户端初始化和只读诊断一致 |
| 项目路径 | `project.config.json`、`miniprogramRoot`、`cloudfunctionRoot` | 根目录和实际文件位置一致 |
| 数据库 | 集合、索引、字段兼容和初始数据 | 所有代码引用的集合已在目标环境创建 |
| 数据权限 | 客户端读写规则、云函数特权路径、角色边界 | 未授权用户和其他用户不能越权 |
| 云函数 | 函数名、运行时、依赖、部署环境和版本 | 目标 EnvId 中存在正确版本且只读调用成功 |
| 云存储 | 是否启用、目录、文件归属和删除路径 | 上传、读取、替换、清除和失败处理可验证 |
| 客户端连接 | `wx.cloud.init` 和调用名称 | 使用完整 EnvId；函数名与部署结果一致 |
| 运维 | 日志、用量、费用提醒和回退方式 | 上线前知道在哪里查看并有负责人 |

集合不会因 `db.collection("name").add(...)` 自动创建。预检表未通过时先准备资源，不得把缺失资源留给首次真机调用发现。

## 登录、头像昵称和手机号

面向用户时固定先说以下三句话，不用“一键登录”暗示可以静默取得资料：

```text
1. 微信身份会由小程序和腾讯云后台自动识别，通常不需要用户填写账号密码。
2. 头像和昵称必须由用户主动选择或填写，不能在后台静默获取；用户可以拒绝、修改或清除。
3. 手机号是另一项独立授权，只有业务确实需要并由用户主动点击时才获取。
```

实现时继续按以下边界处理：

- 微信身份：腾讯云后台可在用户调用后台时自动识别，通常不需要网站式登录页。
- 头像昵称：让用户主动选择头像、填写昵称；使用 `chooseAvatar` 和 `input type="nickname"`，并处理内容安全和用户拒绝。
- 手机号：单独的主动授权能力，使用按钮的手机号授权流程。授权结果需要后台换取，可能存在额度或费用；执行前查看微信按钮文档和当前规则。

必须提供不授权时的合理页面、资料修改和删除路径，并把用途写入隐私说明。

### 旧登录接口兼容审查

维护旧项目时要能识别以下历史写法。它们只用于搜索和迁移，不能作为新项目模板，也不能因为代码还能编译就认定当前仍符合平台规则：

```js
// 历史示例：不要复制到新项目。
wx.getUserInfo({
  success(res) {
    console.log(res.userInfo)
  }
})

wx.getUserProfile({
  desc: '用于完善会员资料',
  success(res) {
    console.log(res.userInfo)
  }
})
```

审查时分别确认：这些调用是否仍在用户主链路、当前基础库和微信版本的真实表现、拒绝后是否可继续使用、隐私保护指引是否匹配，以及是否已经迁移到 `chooseAvatar` 与 `input type="nickname"`。`wx.getUserInfo` 或旧 `wx.getUserProfile` 返回过头像昵称，不代表它们是登录凭证，也不代表新版本能静默取得用户资料。执行迁移前重新打开官方接口与头像昵称文档。

### 前端 openid 反例

下面的写法用于识别安全问题，不得照搬：

```js
// 反例：把身份标识暴露在前端，并让客户端决定要操作哪个用户。
wx.setStorageSync('openid', response.openid)
wx.cloud.callFunction({
  name: 'updateProfile',
  data: { openid: wx.getStorageSync('openid'), profile }
})
```

前端缓存、页面参数、日志或网络请求中的 openid 都不能作为授权依据。云函数从 `getWXContext()` 获取当前调用者身份，自有后台通过服务端登录流程换取并保存身份映射；客户端只提交业务字段。即使旧页面为了显示或兼容暂时保留 openid，也必须把它当作公开输入重新验证，不得据此读取、修改或删除用户数据。优先用无权限含义的业务记录编号替代页面间传递 openid。

## 支付实现与旧 MD5 签名审查

只有用户明确需要支付并完成主体、商户号、类目、资质、费用和退款流程确认后才实现。读取 `cloudbase-wechat-integration`，并以当前微信支付官方文档和官方 SDK 为准。

维护旧项目时搜索固定 MD5、商户密钥进入小程序包、前端拼接签名串等写法。以下仅为迁移反例：

```js
// 反例：客户端持有商户密钥并固定使用 MD5 计算支付签名。
const paySign = md5(`${canonicalParams}&key=${merchantKey}`)
wx.requestPayment({
  ...payment,
  signType: 'MD5',
  paySign
})
```

新实现遵守以下边界：

1. 商户密钥、API 密钥、证书和私钥只存在于可信服务端或受管密钥环境，绝不进入小程序代码、前端配置、日志或项目文档。
2. 服务端使用当前官方接口版本和官方 SDK 创建订单与签名；客户端只接收 `wx.requestPayment` 所需的临时参数。不要把 MD5、RSA 或任何固定算法写成永久规则，执行前核对当前商户平台和官方文档。
3. 金额、商品、订单归属、库存、优惠、幂等、支付结果、回调验签、退款和异常都在服务端校验；不能以客户端回调“成功”作为到账事实。
4. 代码审查发现前端密钥、前端签名、信任客户端金额或固定旧签名流程时，标记为阻塞级问题，迁移并回归后才能体验或提审。
5. 涉及会员、课程、充值、数字商品或其他虚拟服务时，同时进入发布阶段的交易规则核验，不根据旧示例自行判断 iOS 或个人主体一定允许或禁止。

## 分享实现与兼容

每个注册页面默认接入原生菜单分享给朋友。逐路由记录预期 path、query 和接收端结果，公开详情确认内容 ID 对应，私有页验证换号无法读取发送者数据。在真机从右上角菜单发给另一测试账号并冷启动打开。开发时核对 [Page 生命周期与分享回调](https://developers.weixin.qq.com/miniprogram/dev/reference/api/Page.html) 和 [显示分享菜单](https://developers.weixin.qq.com/miniprogram/dev/api/share/wx.showShareMenu.html)：

1. 分享给朋友和分享到朋友圈是两个独立能力，分别检查 `onShareAppMessage` 与 `onShareTimeline`，不要用一个测试结果替代另一个。
2. `wx.showShareMenu` 的菜单能力受基础库版本、平台和当前微信实现限制；接口调用成功不代表安卓、iPhone 和所有入口表现一致。
3. 分享路径和 query 使用稳定、非敏感、可校验的参数。接收者从冷启动进入时必须能看到正确页面，失效或无权查看时有合理降级。
4. 普通页面按钮不能被描述成可以直接代替系统的朋友圈发布流程；页面提示和实际微信入口保持一致。
5. 在 `test-report.md` 分别记录发送端、接收端、设备、微信版本、基础库版本、冷启动结果和未支持平台。

## 代码审查分级与改动边界

所有项目都做通用代码审查，不只审查腾讯云代码。输出使用固定分级：

| 级别 | 含义 | 处理要求 |
| --- | --- | --- |
| 阻塞 | 主链路错误、数据污染、越权、隐私、审核或发布风险 | 修复并回归后才能进入发布 |
| 建议 | 不立即阻塞，但影响可靠性、维护性或可测试性 | 记录决定和处理计划 |
| 可选 | 不影响当前目标的体验或风格优化 | 不得顺手扩大本次范围 |
| 通过 | 当前检查项没有发现需要处理的问题 | 记录检查范围和证据 |

UI、交互流程、状态生命周期、数据结构、云函数、隐私权限和线上核心路径发生变化时，先确认影响和验收标准；不要借修小问题之名顺手重构。局部重复判断、明确无用代码或小缺陷也只能在已确认任务范围内处理，并执行相应测试。

腾讯云代码额外读取 `cloudbase-code-review`。把检查范围、分级发现、处理结果和未验证项写入 `docs/miniapp/test-report.md`。

## 验证证据等级

所有“已通过”声明必须标记下面的最高证据等级；低等级证据不能越级代表高等级结果：

| 等级 | 证据 |
| --- | --- |
| L1 | 静态检查：配置、源码、校验脚本或代码审查 |
| L2 | 微信开发者工具编译通过 |
| L3 | 开发者工具模拟器完成对应流程 |
| L4 | 安卓真机完成对应流程 |
| L5 | iPhone 真机完成对应流程 |
| L6 | 体验版由目标体验成员完成对应流程 |
| L7 | 正式环境完成发布后验证 |

每项记录证据等级、设备或环境、版本、日期、结果和证据位置。没有执行的等级写“未验证”和原因；静态推断不能覆盖真实运行结果，安卓通过也不能代表 iPhone 通过，体验版通过也不能代表正式环境已发布。

## 危险操作默认安全跳过

真实支付/退款、创建真实订单、注销账号、删除或清空数据、解绑/解散/踢出成员、发送真实消息/订阅/外部通知，以及其他不可逆或会产生费用的动作，默认不由 Agent 在真实环境自动测试。

只有同时满足以下条件，才执行某一个明确动作：

1. 用户明确授权该具体动作，而不是笼统同意“全部测试”。
2. 已确认目标账号、数据、金额和环境，优先使用测试账号、测试环境或沙箱。
3. 执行前说明影响、可能费用和恢复方式；无法恢复时明确告知。
4. 该授权只对本次具体动作有效，不得在循环、批量或全量回归中复用。

未执行时在测试报告记录“安全跳过”、原因和需要谁确认，不能标成失败，也不能标成通过。普通页面浏览、静态检查和不改变外部状态的测试可继续进行。

## 测试

涉及 UI 时取出已确认方案的主要任务和代表数据，在微信页面复现同一状态。按[页面构思与打磨](mobile-design-directions.md#同题出稿再看图改一轮)核对首屏、主操作和最易出错的状态；截图比较后实际执行关键动作，把修前、修后和未测项记录到现有测试报告。

至少检查：

- 编译、路由、返回、底部导航和分享
- 新流程重置、返回保留、关闭重开和分享冷启动
- 基础库兼容、实际预览/上传打包范围
- 分享给朋友、分享到朋友圈及不支持平台的降级
- 安卓与 iPhone 真机
- 未登录、拒绝授权、空数据、加载和错误
- 登录、退出账号、资料修改和适用的注销/删除路径
- 旧 `wx.getUserInfo`、`wx.getUserProfile`、前端 openid 暴露和越权扫描
- 弱网、断网、后台失败、上传失败和重复提交
- 数据权限和跨用户越权
- 云端必填、类型、长度、范围、归属和重复请求校验
- 图片昵称内容安全
- 支付金额、订单归属、幂等、回调验签、退款和前端密钥/固定 MD5 扫描（涉及支付时）
- 自有后台域名和 HTTPS；腾讯云环境编号和权限

首次编译出真实小程序页面后，把批准的 HTML 原型和开发者工具截图并排核对；功能通过不能代替视觉验收。固定使用以下视觉验收矩阵：

| 场景 | 必查内容 | 记录方式 |
| --- | --- | --- |
| 安卓真机 | 系统字体、导航、键盘、安全区、按钮和滚动 | 设备型号、系统版本、截图、结果 |
| iPhone 真机 | 胶囊避让、刘海/灵动岛、底部安全区、键盘 | 设备型号、系统版本、截图、结果 |
| 窄屏 | 320px 或可获得的最窄常用设备宽度 | 无横向溢出、按钮和金额不截断 |
| 长昵称 | 至少 12 个中文字符或同等宽度文本 | 换行或截断规则明确，不遮挡金额和操作 |
| 字体放大 | 系统或微信可用的较大字体设置 | 文字不重叠，关键操作仍可见可点 |

任何矩阵项无法验证时，在 `test-report.md` 标记“未测试”和原因，不得写“视觉验收通过”。

把运行命令、设备、结果、最高证据等级、代码审查分级、安全跳过、未验证项和阻塞项写入 `docs/miniapp/test-report.md`。无法操作真机时明确说明，给用户编号清单并等待反馈。

## 阶段出口

核心闭环通过开发者工具和所需真机验证，没有未处理的阻塞级问题，隐私与权限行为符合设计，产物校验通过且测试报告的证据等级、安全跳过和未验证项已更新，才进入发布。

## 工程清理与人工复核

- 开发时给项目自有的每个新增或修改函数写中文注释，说明用途；复杂逻辑补充调用条件、副作用及失败处理。交付时盘点本次交付范围全部自有函数并补齐遗漏，排除第三方和生成代码。
- 发布前盘点前端未用代码、依赖与素材。核对页面配置、动态加载、分包及外部入口后清理；用同样的构建配置比较主包和分包大小，回归相关页面。
- 按锁文件扫描直接与间接依赖的许可证，另查复制的源码、字体、图片、图标的原始授权。记录版本、来源、商用条件和署名等义务，随包保留所需声明。授权不明项交负责人核实、替换或移除。
- 对照实际部署清单检查后端测试路由、调试操作、云函数测试分支及废弃接口。核对旧客户端、定时任务和回调的调用情况，再移除或隔离；用未授权请求验证这些入口不可用。
- 对交付版本运行适配技术栈的依赖漏洞扫描、源码安全扫描与密钥扫描；对登录、角色权限和跨用户数据访问做针对性测试。记录工具、范围、发现、修复及复扫结果，脱敏保存证据。
- AI 提供清理差异、授权清单、安全发现及待核实项。人工逐项复核误删风险、商用条件、测试入口、函数注释和高风险发现，记录复核人及结论。尚未人工确认时标记待复核。
